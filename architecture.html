ARCHITECTURE

Observe the system.
Reconstruct the story.

Cinari is designed as a layered engine: collection feeds a common event model, correlation builds relationships, and analysis turns those relationships into explainable hypotheses.

01DATA SOURCES

Network events · OS signals · traces · logs · metrics · process activity

↓
02OBSERVATION

Normalize low-level behavior into structured events without forcing a new application architecture.

↓
03CORRELATION ENGINE

Build temporal, spatial, dependency, and behavioral relationships between events.

↓
04INTELLIGENCE ENGINE

Generate competing hypotheses, rank likely causes, and quantify confidence from available evidence.

↓
05EXPLANATION

Return a human-readable incident chain with supporting evidence and known uncertainty.

A DIAGNOSTIC, NOT A BLACK BOX

Evidence should be inspectable.

A useful infrastructure diagnosis should allow an engineer to trace the conclusion back to the signals that produced it. Cinari's direction is to make that chain a first-class output of the engine.
